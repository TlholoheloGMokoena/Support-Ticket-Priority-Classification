# AI-Powered Support Ticket Classification System

Predicts ticket **priority** (High / Medium / Low) and **category** from the subject + description using TF-IDF and Logistic Regression, with a Streamlit dashboard for single and bulk classification, ticket history, analytics and model evaluation.

## Important: the included data is synthetic
`data/Support_tickets.csv` is generated by `generate_sample_data.py` so the project runs out of the box. Because the text is templated, **the metrics (priority accuracy about 0.89, category accuracy 1.00) do not reflect real-world performance.** Replace the file with your real export (columns `subject`, `body`, `priority`, `queue`, optional `type`, `created_at`) and retrain to get honest numbers.

## How it works
- `subject` + `body` are merged and cleaned (lowercase, punctuation removed). `answer` is never used, to avoid data leakage.
- Duplicates (same subject and body) and empty tickets are removed. Class weights are balanced to handle imbalance.
- 80/20 stratified split, `random_state=42`. Classes with fewer than 20 tickets are skipped; if no usable category labels exist, the category model is not trained and the app says so.
- The urgent-keyword rule (`support_ticket_classifier.py`) only shows a flag. It never overrides the model, and its impact is evaluated on the Model performance page.

## Run locally
```bash
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python generate_sample_data.py   # skip if you have your own CSV in data/
python train_model.py            # or use "Train model now" in the app
streamlit run app.py
```

## Upload to GitHub
```bash
git init && git add . && git commit -m "Support ticket classifier"
git branch -M main
git remote add origin https://github.com/<you>/AI-Support-Ticket-Classification.git
git push -u origin main
```
Never push private customer data to a public repo: uncomment the dataset line in `.gitignore` first.

## Deploy on Streamlit Community Cloud
1. Push the repo to GitHub (the trained `models/support_ticket_model.pkl` should be included, or use the in-app train button).
2. At share.streamlit.io choose **New app**, select the repo and branch, set the main file to `app.py`, and deploy.
3. Ticket history is stored in SQLite under `outputs/` and is **not persistent** on Streamlit Cloud (it resets on restart). Use an external database for production.

## Layout
`app.py` UI | `train_model.py` training CLI | `support_ticket_classifier.py` pipeline, training, rule flag | `utils/` preprocessing, prediction, analytics + history
